重装系统最麻烦的不是装软件，而是把那些零散的配置重新拼起来。这次我认真做了一遍，并把它记录在这里。

## 为什么用 dotfiles

配置散落在各处的时候，换一台机器就要重新回忆一遍「我当时是怎么设置的」。把它们集中到一个 Git 仓库里，好处有两个：

- 新机器上一条命令就能恢复
- 每次调整都有记录，忘了也能翻回来

## 核心组成

我的配置主要围绕这几件事：

| 用途     | 工具     |
| -------- | -------- |
| 终端     | Ghostty  |
| Shell    | zsh      |
| 提示符   | Starship |
| 编辑器   | Helix    |
| 文件管理 | Yazi     |

## 一个踩过的坑

最初我把仓库下载到了 `~/dotfiles/dotfiles-main/`，比预期多了一层目录。结果所有符号链接都指向了不存在的位置，配置一个都没生效。

看起来像「配置写错了」，实际上只是路径差了一层。这类问题最难查，因为错误信息完全指不到真正的原因。

```sh
# 错误：多了一层
~/dotfiles/dotfiles-main/fish/config.fish

# 正确
~/dotfiles/fish/config.fish
```

## 换 Shell 的取舍

一开始我用的是 fish，它的语法确实更友好。但后来换回了 zsh，原因是：

> 网上 99% 的 Shell 脚本和教程都是 POSIX 语法，fish 里不能直接照抄。

引入一个新工具之前，值得先想清楚它带来的便利，是否大于它造成的兼容成本。

## 小结

配置的关键不是内容多完美，而是**能不能复现**。现在换机器只需要三步：装 Homebrew、拉仓库、建链接。
